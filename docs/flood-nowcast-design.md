# แบบจำลองน้ำท่วมพื้นที่นำร่อง

สถานะ 26 กันยายน 2026: แผนออกแบบและตรวจข้อมูลเข้า ยังไม่มีผลจำลองที่สอบเทียบแล้ว ไม่ใช่ระบบพยากรณ์พร้อมใช้งาน

## เป้าหมาย

พื้นที่นำร่องแสดงบริเวณที่แบบจำลองประเมินว่ามีน้ำขัง ณ เวลาวิเคราะห์ และคาดการณ์ +1/+3/+6 ชั่วโมง โดยมีเวลาออกผล เวลาเก่าสุด/ล่าสุดของข้อมูลเข้า และความไม่แน่นอน เริ่มพื้นที่แสดงผลประมาณ 10 × 10 กม. แต่ขอบเขตคำนวณต้องครอบคลุมพื้นที่รับน้ำและจุดควบคุมการไหลที่เกี่ยวข้อง ไม่ตัดระบบคลองตามกรอบแผนที่

เป้าหมายรอบคำนวณ 15 นาที เป็นเป้าหมายวิศวกรรมที่ต้องทดสอบเวลาและความสดข้อมูลจริง มิใช่รอบอัปเดตที่รับรองแล้ว

## หลักการ

ฝนเชิงพื้นที่และเวลา -> น้ำไหลบ่าหลังหักการซึม -> ท่อ/คลองและการควบคุม -> น้ำไหลบนพื้นผิว 2D -> แผนที่พื้นที่น้ำ พร้อมเปรียบเทียบหลักฐานภาคพื้นดินและดาวเทียม

รักษาสมดุลมวลน้ำ: การเปลี่ยนปริมาตรเก็บกัก = ฝน + น้ำไหลเข้า - น้ำไหลออก - การซึม - การสูบ - การระเหยตามความเหมาะสม ไม่ใช้การรวมคะแนนแล้วระบายสีเป็นผลจำลองน้ำท่วม

## เครื่องมือที่แนะนำสำหรับประเมินความเหมาะสม

- SFINCS: เครื่องคำนวณผิวดิน 2D สำหรับฝน แม่น้ำ และขอบเขตระดับน้ำ ใช้ต้นแบบทดสอบความเร็วและตรวจความเหมาะสมในพื้นที่
- EPA SWMM: ระบบระบายน้ำเมือง ท่อ คลอง จุดรับน้ำ ประตู ปั๊ม น้ำย้อนและน้ำล้น
- การเชื่อมสองแบบจำลองต้องพัฒนา/เลือก coupling ตรวจ timestep หน่วย datum และสมดุลน้ำ ไม่ใช่เชื่อมได้อัตโนมัติ
- HEC-RAS 2D เป็นอีกทางเลือกสำหรับคลอง/แม่น้ำและน้ำท่วมผิวดิน ไม่จำเป็นต้องใช้ทุก engine

## ข้อมูลเข้าและสถานะ

| ข้อมูล | สิ่งที่ใช้ | สถานะที่ตรวจจริง |
|---|---|---|
| ฝน | time series mm ต่อช่วงเวลา + เวลาเริ่ม/สิ้นสุด + ตำแหน่ง; เรดาร์ฝนที่ปรับกับสถานีเมื่อหาได้ | ThaiWater rain_24h มี rain_1h/rain_24h และ rainfall_datetime ทดสอบอ่านสำเร็จ แต่ยังไม่ยืนยันช่วงสะสม/ชุดย้อนหลังที่เพียงพอ |
| ระดับน้ำแม่น้ำ/คลอง | stage hydrograph และ datum ที่ตรงกับแบบภูมิประเทศ | waterlevel_load เชื่อมแล้ว; สถานีใกล้สุดไม่รับรองว่าเชื่อมทางชลศาสตร์กับจุดอ้างอิง |
| คลองเพิ่มเติม | ระดับด้านใน/นอกประตูและช่วงเวลา | canal_waterlevel อ่านได้ แต่พบข้อมูลคละเวลา รวมปี 2023 ต้องคัดทิ้งข้อมูลเก่าและตรวจความหมายฟิลด์ ไม่ถือ canal_out เป็น discharge |
| เขื่อน/การปล่อยน้ำ | discharge hydrograph ของระบบที่เชื่อมถึงพื้นที่ + เวลาเดินทาง | ยังไม่ตรวจแหล่งข้อมูลปฏิบัติการ; ปริมาณเก็บกักอย่างเดียวใช้แทนการปล่อยน้ำไม่ได้ |
| ปั๊ม/ประตู/ท่อ | พิกัด ความจุ เส้นโค้งปั๊ม ทิศทาง ระดับท้องท่อ ระดับปลายทาง สถานะตามเวลา | ยังไม่มี ต้องได้จากผู้ดูแลระบบระบายน้ำ |
| ภูมิประเทศ | DTM สำรวจ ถนน คันกั้นน้ำ ช่องลอด หน้าตัดคลองและ datum | ยังไม่มีข้อมูลระดับถนนที่ตรวจคุณภาพ; Copernicus GLO-30 เป็น DSM 30 ม. ใช้สำรวจเบื้องต้น ไม่อ้างความแม่นยำถนน |
| พื้นผิว/ดิน | พื้นที่ซึมน้ำและผิวแข็ง roughness ความชื้นก่อนเหตุการณ์ | ยังไม่มีชุดที่จัดเตรียมเข้าระบบ |
| ขอบเขตปลายน้ำ | ระดับน้ำตามเวลา รวมอิทธิพลน้ำหนุนถ้าเกี่ยวข้อง | ต้องระบุจุดเชื่อมจริงก่อนเลือกสถานี |
| หลักฐาน | ภาพถ่าย/ดาวเทียม พร้อมตำแหน่ง เวลา และขอบเขตที่เห็น | 4 ภาพของผู้ใช้ ถ่ายราว 09:00 น. 26 ก.ย. 2026 เวลาไทย ตำแหน่งอ้างอิงตามผู้ใช้; GFM WMS ใช้ได้ แต่ภาพรวมช่วงหลายวันไม่ใช่หลักฐานเวลาเดียวกัน |

## การทำงานเป็นรอบ

1. เก็บข้อมูลดิบแบบ append-only พร้อม observed_at, received_at, source, units, datum, validity และค่า missing ที่ไม่แปลงเป็นศูนย์
2. คัดข้อมูลเสีย/เก่า แก้เวลาสถานีให้ตรงกัน เก็บประวัติฝนเป็น time series ไม่บวกฝนสะสม 24 ชม. ซ้ำทุกรอบ
3. ระบุสถานีและขอบเขตด้วยเครือข่ายการไหล ไม่เลือกจากระยะทางอย่างเดียว
4. เริ่มจากสภาพน้ำก่อนเหตุการณ์และ warm-up แบบจำลอง รับฝน ระดับน้ำ และการเดินเครื่องตามเวลา
5. คำนวณ current-state estimate และ forecast ใช้ฝนคาดการณ์สำหรับอนาคต แยกจากฝนวัดจริง
6. รันหลายสมมติฐานเฉพาะค่าที่ไม่ทราบ เช่น ความสามารถระบายและฝนคาดการณ์ รายงานความไว/ช่วงผล ไม่อ้างความถี่ ensemble เป็นความน่าจะเป็นที่สอบเทียบแล้ว
7. เปรียบเทียบหลักฐานแล้วปรับค่าที่มีเหตุผล ไม่เพิ่มน้ำเพื่อบังคับให้ตรงรูป หากใช้รูปใดสอบเทียบต้องใช้หลักฐานอีกชุดประเมินผล
8. ส่งผล GeoTIFF/tiles/GeoJSON พร้อม run_id, model_version, issued_at, valid_at, input_cutoff, observed data age, assumptions, calibration status

## ลำดับการพัฒนาและเกณฑ์ผ่าน

A. Data audit: ระบุ DTM/datum ระบบคลองและท่อ จุดรับ/ระบายน้ำ ฝนย้อนหลัง และ operation logs ที่มีจริง ยืนยันสิทธิ์นำข้อมูลมาใช้งาน ข้อมูลจำเป็นที่ขาดทำให้ยังไม่ออก operational nowcast

B. Hindcast: จำลองเหตุการณ์ก่อนและถึง 09:00 น. ของวันที่ 26 โดยใช้ข้อมูลตามเวลานั้น ตรวจจุดที่มีน้ำและจุดที่ไม่มีน้ำ รวมถึงขอบเขต ไม่อนุมานความลึกจากภาพถ่ายทั่วไป ภาพทั้งสี่อย่างเดียวไม่พอรับรองความแม่นยำพื้นที่ทั้งหมด

C. Validation: เก็บชุดเหตุการณ์/ตำแหน่งอิสระ ตรวจ hit/miss/false alarm, critical success index, extent overlap, เวลาเริ่มท่วม/ลด และ water-balance residual ทดสอบความไวต่อขนาดกริด/ช่วงคำนวณและการระบาย

D. Shadow mode: รันอัตโนมัติแต่ติดป้ายผลทดลอง ติดตาม latency และคุณภาพ input ก่อนเปิดให้ใช้จริง หากข้อมูลสำคัญขาดให้หยุดอ้างว่าเป็นผลปัจจุบันหรือแสดงสมมติฐานชัดเจน

E. UI: แยกสี observed / modeled / unknown พร้อม slider เวลา ไม่แสดงพื้นที่ไม่มีข้อมูลเป็นปลอดน้ำ ไม่เปลี่ยนกล้อง/ภาพเก่าเป็นรายงานปัจจุบัน
